# ADR 0014 — Overlay Naming & Split-Horizon DNS

**Status:** Proposed — a **net-new, currently un-milestoned** capability (the Implementation Plan carries only a deferred one-liner, "Overlay DNS/naming — Nebula's `lighthouse.dns` for name→overlay-IP resolution, if services need names not IPs," plus a UI-6/M9 placeholder). This ADR promotes it to its **own milestone, sequenced after M7**, riding the M6 signed-bundle machinery; the cross-platform appliers explicitly depend on M10. This draft incorporates a three-architect design panel (security-purist / smallest-increment / cross-platform-durability lenses), two adversarial red-team passes (security + 15-years-of-production-DNS ops), and a dedicated resolver-architecture face-off (central-appliance-pair vs per-host-embedded). **Rev (2026-07-15b):** adds the **default-forward path** (ask C) — per-netblock default forwarders — so making Pilot the first-stop resolver has a defined answer for non-mesh, non-split-horizon queries instead of blackholing them.
**Date:** 2026-07-15
**Decision owners:** Chris Hyde (+ a second approver per dual-control, where it applies)

## Context

The mesh is **IP-native today**: `core-api` routes over the overlay by IP, IPAM is the only "resolver" in the system (netblocks, not names), and the overlay CIDR is `100.64.0.0/16` (CGNAT). The pain is already live — the admin console is **mesh-only**, so operators improvise `hosts` entries / split-horizon DNS just to reach it ([[Nebula Control Plane - Runbook - Entra ID SAML SSO for the Console|Entra runbook]]:64). Two asks define the feature:

- **(A) Auto-DNS** — every mesh node gets a **unique DNS name that matches its certificate**: `<label>.<mesh-domain>` → `overlay_ip`, plus reverse `PTR` in `64.100.in-addr.arpa`.
- **(B) Split-horizon forwarding** — the mesh admin defines **domains forwarded to other internal DNS servers reachable over the mesh**, so those zones (and the mesh zone) resolve **only on-mesh** and **per group**: e.g. `corp.internal → [100.64.0.10, 100.64.0.11]` scoped to `backend`; `frontend` must never receive that zone.
- **(C) The default-forward path (the implied third requirement).** Making Pilot the host's *first-stop* resolver forces a question the operator never explicitly asks but must be answered: **where does *every other* query go** — the names that are neither a mesh name nor a configured split-horizon zone? If undefined, turning the resolver on **blackholes all public/other DNS**. The answer must be **per-netblock**: netblocks map to sites/regions, each with its own most-local DNS cache, so the bulk of queries should stay on the nearest resolver rather than funnel to one place. This ADR handles it with **fleet-default forwarders + per-netblock overrides + a non-destructive fall back to the host's existing upstreams**.

Six properties of the system shape the design; the first is the linchpin and the rest are why the delivery is nearly free.

1. **Certificate names are NOT unique and NOT DNS-safe (the linchpin the whole feature rests on).** The name originates as host-supplied `CSR.RequestedName`, flows **verbatim** — zero normalization, format, length, case, or uniqueness validation — through the single chokepoint `enrollment.deviceName()` (`internal/enrollment/enrollment.go:1163`) into `signer.Template.Name`, and the signer rejects **only** the empty case (`signer.validate`, `internal/signer/signer.go:293`; `ErrEmptyName`, `signer.go:69`). The fallback name `"dev-"+base64url(pubkeyhash)[:10]` is **not a valid DNS label** (`_`, mixed case). `enrollments.device_name` has **no** unique constraint (`internal/store/migrate/sql/sqlite/000003_enroll.up.sql:24`). `devices.name` *is* `UNIQUE` (`000002_ipam.up.sql:5`), but `ipam.ensureDevice` uses `FirstOrCreate`-by-name (`internal/ipam/ipam.go:330-340`), so two physically distinct hosts (distinct keys/certs/overlay-IPs) requesting the **same** name silently **collapse onto one `devices` row** — the constraint never trips, so name is **not** a 1:1 host key. The only genuinely stable, unique keys are **`overlay_ip`** (stable across renewal — renew re-signs the same IP, `coreapi.go:231`,`:618-625`) and **`fingerprint`** (unique but **rotates every renewal**). `heartbeats.device_name` is untrusted self-assertion; `enrollments.device_name` is Core-authoritative.

2. **The signed-bundle → render → drift-revert pipeline already exists and is the delivery mechanism.** Fleet config (firewall, lighthouses, blocklist) rides inside `bundle.Bundle`, signed with the **config-signing key** via JWS ES256, verified by Pilot against a **pinned pubkey** before anything inside is trusted, rendered byte-identically into `config.yml` by `bundle.RenderNebulaConfig` (`internal/bundle/bundle.go:93`) → `internal/nebulaconfig` (`render.go`, `template.yml.tmpl`), on **all** of enroll / renew / `apply_bundle` / drift re-assertion (`internal/drift/drift.go:88-102`). Each feature is sourced **live at bundle-build time** from a per-feature `Registry` (`internal/revocation`, `internal/lighthouse`, `internal/gatewayreg`) via **fail-open** callbacks wired at **two** build sites — `coreapi.assembleBundle` (renew / `GET /v1/config`) **and** `enrollment.buildBundle` (fresh enroll); forgetting one makes renewed vs freshly-enrolled hosts diverge. Each `Registry.Active()` returns a **deterministically sorted** set so the bundle is byte-stable (else Pilot's drift monitor churns forever). Optional fast propagation = a rollout **lane** + a bundle `Version` int + a heartbeat applied-version + the `apply_bundle` command (the 7.1b blocklist-lane pattern). The migration ceiling on disk is **000031** → the next is **000032**. `bundle.Bundle` already carries an **unused** `Config json.RawMessage` passthrough (`bundle.go:59`) — we will **not** use it (typed + signed is safer).

3. **Nebula's own built-in DNS is present but insufficient for both asks.** Verified in the pinned `nebula v1.10.3` (`go.mod:22`), `dns_server.go` answers `A`/`AAAA`/`TXT` for `cert-name → overlay-IP` from the host map, enabled via `lighthouse.serve_dns` + `lighthouse.dns {host,port}`. It has **no forwarding and no recursion** (returns empty on a miss), is **fleet-global** (no per-group views), and its host-map is a per-lighthouse eventually-consistent cache (multi-lighthouse HA → split-brain `NXDOMAIN`). It can **weakly** cover ask (A) and does **nothing** for ask (B). We leave it **off**.

4. **The tunnel is already decoupled from Pilot's lifetime.** The pilot unit runs `KillMode=process` (`internal/pilotservice/service_linux.go:204`, guarded by a regression test `service_test.go:47`), and [[Nebula Control Plane - ADR 0003 - Pilot and Nebula Self-Update and Distribution|ADR 0003]] Phase 3 re-adopt (`internal/supervisor` `AdoptPID`/`adoptOnce`, acceptance tests `supervisor_test.go:172-216`) means a pilot **crash leaves `nebula` running** and the restarted pilot **re-adopts** it. So a resolver running **in-process** with Pilot **cannot drop a tunnel** by crashing. This single fact voids the central pair's strongest structural claim (see §"The resolver fork").

5. **`miekg/dns` is already an indirect dependency.** `github.com/miekg/dns v1.1.72 // indirect` (`go.mod:65`), pulled in via nebula. An in-process Go resolver in Pilot adds **no new release-signing TCB root** and ships as **one cross-platform binary**.

6. **Groups are server-assigned, cert-baked, and knowable from `overlay_ip` at Harbor** — the *exact* input the firewall compiler already consumes to produce a host's per-group policy. A host never asserts its own groups. This hands the per-group split-horizon compile (ask B) to the bundle builder for free (see §"The model in detail").

Two more facts about the name→IP source of truth: the authoritative binding is **`enrollments` (latest `status='issued'` per `overlay_ip`)**, but it must be **intersected with the live fleet** (`heartbeats` within `StaleAfter=5m`, or `ip_allocations.LiveAddrs`) because the reaper **frees an IP and deletes the heartbeat but leaves `enrollments.status='issued'`** → an enrollments-only zone maps a name to a freed/reassigned IP (a ghost record).

## Decision

Deliver both asks on the existing signed-bundle spine with **one new moving part: a per-host embedded Go resolver (`miekg/dns`, already in-tree) running inside Pilot, answering only from the latest verified, cached bundle** — no external daemon, no live query to Harbor on any lookup, no new TCB root, and split-horizon that is **confidential by construction** (a non-member host's bundle never contains another group's zone). Name uniqueness is fixed first, as a standalone **Phase 0** that is valuable independent of DNS. The user's instinct — a shared on-mesh `unbound` pair — is preserved as a **narrowly-scoped, default-OFF escape hatch** for ask (B)'s *forward* half only, where a mature shared cache actually pays off, without ever moving the per-group decision or ask (A) off the host. And because making Pilot the first-stop resolver means it must answer for *everything else* too, the design defines a **default-forward path** (ask C): **per-netblock** default forwarders — with a non-destructive fall back to the host's existing upstreams — so non-mesh, non-split-horizon queries stay on each site's most-local cache instead of being blackholed.

**Names are a human-convenience layer, not a security boundary.** Nebula authenticates every peer by **certificate** and the default-deny central firewall gates reachability, so a wrong/stale/poisoned name can neither forge identity nor bypass the firewall. This framing is what lets us safely accept auto-derived names, fail-open sourcing, drift-cadence node records, and a bounded cert-Name↔label convergence window. It is *also* the one place the framing has teeth — see the squatting residual in §"Consequences".

## The name model (ask A) and the Phase-0 prerequisite

- **FQDN** = `<label>.<mesh-domain>` (e.g. `web-3.mesh.internal.`). `<label>` is a validated, unique RFC-1123 LDH label **equal to the cert `Name`** (ask A says "matches its certificate," and putting the name in the *signed cert* makes control-plane/lighthouse names cryptographically non-redirectable → P10). `<mesh-domain>` is a **site setting** (default `mesh.`). **The production recommendation is a subdomain of a domain you own** (e.g. `mesh.<yourdomain>`) so publicly-trusted TLS can be issued for mesh names via the existing `autotls` DNS-01 flow (see §"TLS on mesh names"); reserve the ICANN-private `.internal` for a deliberately offline / private-CA deployment. It is set once, server-side; a host never asserts it; changing it renames the fleet → dual-control-gated.
- **Anchor:** every record binds to **`overlay_ip`** — never `name` (collapses) and never `fingerprint` (rotates). Forward `A` = `<label>.<mesh-domain> → overlay_ip`; reverse `PTR` in `64.100.in-addr.arpa`.
- **Name authority = auto-derive + auto-suffix (decided).** `deviceName()` normalizes `RequestedName` → LDH label (lowercase; IDNA/punycode any non-ASCII; collapse illegal runs to `-`; strip leading/trailing `-`; truncate to 63). If empty/invalid, derive a **legal** deterministic fallback from the stable `overlay_ip` (e.g. lowercased base32 of the octets — this kills the `dev-`+base64url bug). On collision with a label already bound to a **different** `overlay_ip`, append a **deterministic, `overlay_ip`-ordered** suffix (`web` → `web-2` → `web-3`) — never random or time-sequential, or the bundle stops being byte-stable. Cloud-attested/token enrollment is unattended and must never wedge, so auto-suffix is the default; an attended-enrollment "hard-reject on collision" toggle is a future option.

### Phase-0 fixes (the prerequisite), anchored to `overlay_ip`

1. **Chokepoint** — normalize + uniquify + reserved-refuse in `deviceName()` (`enrollment.go:1163`), applied on **all** issue paths (token, attested, sso, approve).
2. **Backstop** — `signer.validate()` (`signer.go:293`) rejects any `Name` that is empty, not a legal LDH label, or that shadows a reserved control-plane/lighthouse label. Defense-in-depth so **no** issuance path can mint a bad or CP-shadowing cert name (mirrors the existing two-site propose+commit enforcement style).
3. **Authoritative binding** — a new `dns_names(overlay_ip PK, label UNIQUE, assigned_at)` table: the label is a **property of the IP allocation**, assigned once at first issue and **read back / reused on every renewal** (never re-derived from a possibly-changed `RequestedName`). This keeps cert `Name` == DNS label stable across renewals and gives the label a *real* DB `UNIQUE` (which a column on the multi-row `enrollments` table cannot).
4. **Kill the silent collapse** — re-key `ipam.ensureDevice` (`ipam.go:330-340`) on **`overlay_ip`**; a name resolving to a *different* `overlay_ip` becomes a **hard error surfaced to the operator**, not a `FirstOrCreate` merge. (Independent correctness fix; DNS just makes it load-bearing.)
5. **IP-recycle safety (red-team fix).** Because `dns_names` is keyed on `overlay_ip` with reuse-on-renewal, a recycled IP would otherwise hand a new host the *previous* owner's label (misdirection) or hard-fail its enrollment forever. **The reaper MUST clear the `dns_names` row when it frees an IP** — the label lifecycle is tied to the *allocation*, not the IP value. (This also means the live-intersect debounce/hysteresis for the *zone* must be reconciled with reaper timing so the two do not fight.)
6. **Reserved namespace (P10)** — control-plane/lighthouse labels are baseline-owned, un-removable, minted from `internal/lighthouse` + `policy.GroupControlPlane`/`GroupLighthouse` (`policy.IsReservedGroup`, `internal/policy/policy.go:28`; `GrantsReservedGroup`, `:33`). The reserved set is a **pattern** (`lighthouse-<n>` for all n) plus a forward-looking CP allowlist, so a host cannot squat `lighthouse-5` *before* that role exists.
7. **Legacy names / migration 000032** — there is no rename API and live certs carry bad/duplicate names. Migration `000032` backfills `dns_names` over every live `overlay_ip` in `(created_at, overlay_ip)` order, resolving collisions with the same deterministic suffix. **The served zone is built from `dns_names` (`overlay_ip`-anchored), not from the cert `Name` on the wire — so DNS is correct immediately;** each host's cert `Name` converges to its assigned label at next renewal (bounded by cert lifetime). The transient cert-Name ≠ zone-label window is safe because DNS is not a security boundary here.

## The resolver fork: per-host embedded vs a central on-mesh pair

The one genuinely contested decision. A face-off (advocate for each, each steelmanning the other, neutral max-effort judge, all grounded in-repo) scored both against this project:

| Axis | Central pair (`unbound` ×2) | **Embedded (Pilot, `miekg/dns`)** |
|---|---|---|
| **P3 availability (Harbor/resolver down)** | LOSS — a new resolution dependency; both-down = fleet-wide name outage | **WIN** — local verified bundle; tunnel-equal availability, zero external dep |
| **P9 surface** | LOSS — two queryable mesh services added | **WIN** — loopback stub; no queryable service |
| **P10 non-redirectability** | LOSS — mutable appliance, runtime precedence; a compromised appliance redirects | **WIN** — compile-time no-shadow invariant, name in the signed cert |
| **TCB cost** | LOSS — `unbound` is fleet-RCE if bundle-fetched, else distro-trust/version-skew | **WIN** — `miekg/dns` already in-tree (`go.mod:65`); zero new root |
| **Per-group split-horizon (B)** | LOSS — runtime source-IP→`view` ACLs = a second policy engine outside Harbor, fails open on misconfig | **WIN** — confidential by construction; other groups' bytes never sent |
| **Cross-platform host integration** | WIN — point split-DNS at 2 stable VIPs; deliverability already routine | LOSS — loopback split-DNS delivery unverified (needs a spike) |
| **Resolver maturity (TTL/EDNS/TCP/neg-cache)** | WIN — `unbound`: serve-stale, neg-cache, DNSSEC | LOSS — thin stub; borrow CoreDNS plugins |
| **Observability at 1000 hosts** | WIN — two boxes; central query logs, standard tooling | LOSS — 1000 instances; needs a telemetry pipe |
| **Effort / fit with bundle machinery** | LOSS — a new subsystem (zone-builder, appliances, HA, views) | **WIN** — rides the existing bundle/render/drift pipeline; one binary |

**Decision: embedded.** Two axes decide it, both non-negotiable for this project:

- **Per-group split-horizon *confidentiality* (ask B, a stated requirement).** Groups are server-assigned/cert-baked/`overlay_ip`-knowable (fact 6) — the exact input Harbor already consumes to compile per-group firewall policy. Embedded computes each host's forward-zone union **in that same build pass**; a `frontend` bundle simply *never contains* `corp.internal`. Confidentiality is **structural (bytes never sent)**. The central pair *inverts* this: one shared appliance holds **all** groups' zones and must reconstruct per-host authorization at query time via source-IP→`view` ACLs — a second policy engine, guaranteed to drift, whose confidentiality degrades to an ACL-correctness invariant that **fails open** on misconfig.
- **P3-for-names.** The project *explicitly* extends P3 to resolution ("Harbor down must never break name resolution hosts use on the wire"). Embedded makes resolution a pure local-data property answered from the same cached bundle held for the tunnel's lifetime — **zero external dependency**. The central pair adds a name-resolution dependency (both appliances down = names go dark, tunnels survive). This holds even for ask (B)'s forward half: the forward *targets* are the operator's on-mesh internal DNS servers, which a host reaches **directly** — inserting an appliance in front only *adds* a failure point.

**The central pair's marquee advantage is already owned.** Its strongest structural claim — "a resolver crash never touches the tunnel supervisor" — is **already true** here via `KillMode=process` + ADR 0003 re-adopt (fact 4). A `recover()`-walled resolver goroutine (or, trivially, a second supervised child — the supervisor is generic) cannot drop a tunnel by construction. Its honest wins (maturity, observability) are **workload-light and addressable**, not architectural: ask (A) is authoritative-static (no negative cache / recursion / poisoning model to build), ask (B) forwards only to **cert-authenticated on-mesh** upstreams (deleting the off-path-spoofing threat that justifies most of `unbound`'s machinery), leaving a *thin* TTL+neg-cache+TCP-fallback+failover need that **CoreDNS's `cache`/`forward` plugins provide as an embeddable Go library** (same in-tree `miekg/dns`, existing release-signing key, zero new root). Observability is reconstructed by emitting resolver counters into the heartbeat/telemetry Pilot already ships.

## The model in detail

- **Ask A (mesh names + PTR): authoritative from the local signed bundle.** Harbor's bundle-builder emits the `A`/`PTR` zone from `enrollments(issued) ∩ live-fleet` (the mandated intersect that drops reaper ghosts; add hysteresis/debounce on the live boundary, reconciled with fix #5 above) plus baseline CP/LH names, as a new **typed, sorted** `bundle.DNS` field under the existing config-signing JWS. The resolver answers **authoritatively** — instant `NXDOMAIN`, no negative cache, no recursion. **P10 = a compile-time no-shadow invariant** in the same compiler that already rejects bad policy (no forward zone may overlap the mesh domain or a baseline name — enforced at propose *and* commit, mirroring 7.2 "can't-blocklist-the-control-plane"); authoritative mesh records are evaluated **before** any forward zone.
- **Ask B (per-group forward zones): the group DECISION stays in the bundle; forwarding is direct.** Harbor compiles *this host's* group-union of forward zones at bundle-build (the firewall-policy pass); the embedded stub forwards **only those zones** straight to the internal DNS **overlay IPs** (over the mesh), with a thin TTL/neg-cache + TCP-fallback + two-upstream failover borrowed from CoreDNS-as-library. **Split-horizon targets are validated inside `100.64.0.0/16`** at input, propose, and commit — an internal zone must resolve *over the mesh* (that is what makes it split-horizon).
- **Ask C — the default-forward path: where *everything else* goes (per-netblock).** The resolver runs a fixed **resolution order** per query: **(1)** mesh zone (`.<mesh-domain>`) + overlay `PTR` → answer **authoritatively** from the bundle (`NXDOMAIN` for a non-live mesh name); **(2)** a split-horizon zone in *this host's* per-group set → forward over the mesh to its overlay-IP servers; **(3) everything else → the host's *default forwarders***, by precedence: **(a) per-netblock override** → **(b) fleet-wide default** → **(c) the host's *captured pre-existing upstreams*** (non-destructive: queries go exactly where they went *before* Pilot took over) → **(d) `SERVFAIL`, logged** (never a silent blackhole). Default forwarders are typically **underlay/local** addresses (a site's VPC resolver / on-prem cache) reached over the host's **normal interface, not the mesh** — the whole point is to keep the bulk of traffic on the *most-local* cache. They are **per-netblock** because netblocks map to sites/regions: Harbor reads each host's netblock from **`enrollments.sub_range`** (the netblock name persisted at enroll, migration `000029`) at bundle-build and emits that host's forwarder set. **Loop guard:** a forwarder may never equal Pilot's own listener address.
- **Two integration postures (ask C is what makes the second one safe).** *Scoped* (MVP/Phase 1): OS-native split-DNS routes **only** mesh + forward zones to Pilot (loopback); the host keeps its own resolver for everything else, so Pilot never sees step (3) and default-forwarders lie dormant. *Primary* (Phase 2, and **required** for capture-mode): the host points its **default** resolver at Pilot, which runs the full resolution order above — uniform across OSes, no per-OS split-DNS routing needed. Without the default-forward path the *primary* posture would blackhole all non-mesh DNS; **with** it, enabling Pilot-as-first-stop is non-destructive by construction (step 3c). We keep step (3) **loopback-local** — it is a host stub-forwarder, never an open recursive resolver exposed to peers.
- **Crash boundary (already handled — keep it, add one belt).** Resolver query handlers run `recover()`-walled with in-flight / response-size / rate caps (defeats a malicious forward-target's flood/panic). Given `KillMode=process` + re-adopt already protect the tunnel, a separate resolver *child* is optional hardening, not a prerequisite — but it is cheap on the generic supervisor. **Keep the `KillMode=process` regression test** (`service_test.go:47`).
- **Fail-open source → keep-last-good sink (red-team P3 fix).** The `DNSSource` callback is **fail-open** at both build sites (a transient DB error must never fail an enroll/renew or drop a tunnel). But Pilot must therefore treat an **absent/empty** DNS section as **"keep last-good," not "authoritatively empty"** — distinguished by a presence/version flag — or a sub-second Harbor blip would RCU-swap a host's zone to empty and blank resolution. Reload is an **atomic in-memory zone swap** on `apply_bundle`/drift from the *verified* bundle.
- **Host integration (scoped posture): render split-DNS from the bundle, drift-revert it — never rewrite `/etc/resolv.conf`.** (In the *primary* posture the host's default resolver is pointed at Pilot's bind instead, and step (3) of the resolution order handles the rest.) On most distros `resolv.conf` is a manager-owned symlink (systemd-resolved / NetworkManager / dhclient); seizing it ping-pongs and forces loosening `ProtectSystem=strict`. Instead use each OS's native **per-domain split DNS**: systemd-resolved routing-domains via `resolvectl` (Linux MVP), Windows **NRPT**, macOS `/etc/resolver`. **Prefer a loopback high-port bind** (e.g. `127.9.53.53:5354` — no `CAP_NET_BIND_SERVICE`, `ProtectSystem=strict` intact, avoids the systemd-resolved stub on `127.0.0.53`/`.54`). **One genuine unknown must be spiked before Phase 1 commits:** loopback-bind delivery when systemd-resolved routes the query *via the nebula link*. **Verified fallback** if the spike fails: bind the host's **own overlay-TUN address** with the central firewall **denying `:53` from all peers** — a normal on-mesh address (the reachability the central pair relies on) that stays host-only.
- **Firewall interlock.** Under the allow-only default-deny DSL, publishing a forward zone **auto-derives a companion allow** for `udp/53` **and** `tcp/53` (truncation/large PTR) from the scoped groups to each forward target, *and* a **publish-time firewall-path check** warns/blocks if the publishing groups lack a `:53` path. Host→local-resolver traffic is loopback and never traverses the nebula firewall. (The auto-allow is a least-privilege crossing — see §"Consequences".)
- **Observability.** Emit resolver counters into the existing heartbeat/telemetry (queries, `NXDOMAIN`, forward-failure, cache-hit, upstream latency); full query-log opt-in/sampled. Add a day-2 `harbor dns doctor` reporting each host's *asserted-vs-effective* resolver path, so "DNS integration degraded" is a visible fleet-health signal, not a silent mystery.

### The escape hatch (default OFF) — honoring the shared-`unbound` instinct where it pays

Permit an optional **shared on-mesh forward-cache** (an `unbound`/CoreDNS pair, co-located on the always-on lighthouse boxes → **zero new machines**) **for ask B's forward half only**, enabled per-deployment when the internal upstreams are heavy/flaky/deep enough to want a mature shared cache. Strict boundary:

- It is a **dumb forwarder/cache** — **the per-group decision NEVER moves to it.** Each host still forwards only its *own* bundle-selected zones *to* it, so it holds **no** group-authorization and can leak nothing structural.
- It **binds an overlay VIP only, firewall-gated**, and **rides the same config-signing JWS pull + atomic last-good symlink** as Pilot (P11 holds; P3-*degraded*-not-broken, and only for the forward half).
- **Ask A and control-plane names are *never* served by an appliance** — they stay 100% local.

This captures `unbound`'s forwarding maturity + 2-box forward observability precisely where they become load-bearing, without surrendering either decisive axis.

## Delivery and governance

**Bundle field** — `bundle.DNS *DNSConfig` (typed, `omitempty`, inside the config-signing JWS; **not** the unused `Config json.RawMessage` passthrough):

```
DNSConfig{
  Domain   string                                              // mesh apex (site setting)
  Zone     []Record{ Label, OverlayIP }                        // ask A, auto-derived, sorted, + PTR
  Forwards []Forward{ Domain; Servers []overlayIP; Groups []string }  // ask B, per-host-compiled, sorted
  DefaultForwarders []string                                   // ask C — per-host-resolved from the host's netblock (sub_range); underlay allowed; where step-(3) queries go
  CaptureUpstream   bool                                       // ask C fallback — when set + no forwarders configured, use the host's captured pre-existing upstreams (non-destructive)
  Version  int                                                 // rollout axis (forwards + default-forwarders)
  Present  bool                                                // keep-last-good discriminator
}
```

- **Three sources of truth:** node zone (ask A) auto-derived in a new `internal/meshdns` package (Registry-shaped, mirrors `internal/revocation`/`lighthouse`/`gatewayreg`) from `enrollments ∩ live`, baseline CP/LH injected; forward zones (ask B) an **operator-managed** registry in the same package (`Add/Remove/List/Active`, audited into the hash-chain, sorted, validated: legal FQDN, servers in-overlay, no overlap with the mesh apex or a CP/LH suffix); and **default forwarders (ask C)** — a fleet-wide default (site-setting) plus a **per-netblock override** registry (`dns_netblock_forwarders`, audited), resolved **per host** at bundle-build from the host's `enrollments.sub_range` netblock (override → fleet default; the capture fallback is decided client-side). Default-forwarder targets are validated as syntactically valid resolver addresses and **not** equal to Pilot's own listener (loop guard); unlike split-horizon targets they **may be underlay/public** (the site's local cache is the point).
- **Two build sites, fail-open** — thread a `DNSSource` into **both** `coreapi.assembleBundle` and `enrollment.buildBundle`; a parity integration test cloned from `TestRenewBundleCarriesBlocklist` asserts fresh-enroll and renew emit identical DNS sections.
- **Rollout split by blast radius** — **node zone → drift/renewal cadence, no lane, does not bump `Version`** (high-churn, low-risk, self-converging; "freeze on unhealthy canary" is meaningless for a name map). **Forward zones → their own `dns` rollout lane** (reuse the 7.1b engine: add a `dns` value to `rollouts.lane`, `bundle.DNS.Version` + heartbeat `applied_dns_version`, `apply_bundle` when behind, canary→waves, **freeze/rollback on unhealthy canary**). *MVP ships without the lane (drift cadence); the lane lands in Phase 3.*
- **Governance** — forward-zone edits are a privileged fleet-MITM primitive → **dual-control publish** (new `internal/dualcontrol` Kind `dns.forward`, quorum ≥2) + RBAC perm `dns:write` + **step-up MFA**; the P10 shadow-refusal is enforced **server-side at BOTH propose and commit** (reusing the 7.2 resolver: `adminapi.fleetGroupMap` + `lighthouse.Registry` + `policy.GroupControlPlane/GroupLighthouse`). Node records are auto-derived → **no** dual-control. The `mesh_domain` apex site-setting is dual-control-gated (renames the fleet). **Default-forwarder edits** (fleet default and per-netblock overrides) redirect a host's *entire* non-mesh DNS — a public-DNS MITM/exfil surface — so they are **dual-control + audited** like forward zones; unlike split-horizon targets they **may be underlay/public** (the site cache is the point) but are **loop-checked** against Pilot's own listener.
- **CLI** (strict subset per `cli_surface_test.go`): `harbor dns names|zone` (compile/debug, `--host|--group`), `harbor dns backfill` (one-time), `harbor dns forward add|remove|list` (dual-control on commit), `harbor dns forward-default set|show` (fleet default + `--netblock <name>` override, dual-control on commit), `harbor dns status` (lane convergence, Phase 3), `harbor dns doctor`. Plus the OpenAPI contract-test + `cli_surface_test` entries per the established recipe.
- **Console** — deferred, API-first (routine) → the existing **UI-6** "Naming & DNS" placeholder.
- **Migration `000032`** (ceiling on disk is `000031`): `dns_names(overlay_ip PK, label UNIQUE, assigned_at)` + `dns_forward_zones(id, domain, servers JSON, groups JSON, active, timestamps)` + `dns_netblock_forwarders(netblock_id, servers JSON, timestamps)` (ask C per-netblock override) + the `applied_dns_version` heartbeat column. `mesh_domain` **and the fleet-default forwarders** ride the existing site-settings mechanism (no new table). **Applied manually on the box before the binary swap** (`serve` never runs `migrate.Up`).

## Security posture

- **P3 (off the data path):** resolution is served entirely from the last verified, cached bundle — no per-lookup query touches Harbor or any anchor; `DNSSource` is fail-open at the source and keep-last-good at the sink; forward targets are peer mesh resolvers reachable independent of Harbor. The **default-forward path** is *extra* P3-robust: those forwarders are the host's local/underlay caches reached **off-mesh**, so they keep answering even if the *mesh itself* is down — the cached bundle only supplies *which* forwarders, never the answers. *Refused:* option ④ (a lookup that hits Core/lighthouse).
- **P9 (names resolve only inside the mesh; no open resolver *to peers*):** the resolver binds loopback (or, fallback, the host's own TUN address `:53`-denied from peers), so **peers can never query it** — it serves only the local host. For that local host it *does* run the resolution order, including forwarding step (3) to the default forwarders; that is a **host-local stub-forwarder**, not an open recursive resolver exposed to the network. Mesh names never leave the host except as a forward to an in-mesh authoritative server; default-path queries leave via the host's normal interface to its local cache, exactly as they did before. **The public enrollment gateway gains no resolver.** *Refused:* any bind that lets a **peer** reach recursion/forwarding (except the opt-in escape-hatch cache, VIP-only + firewall-gated); a resolver on the gateway.
- **P10 (control-plane names resolvable & non-redirectable):** CP/LH records are baseline-owned, un-removable, injected from the registries; the name lives in the *signed cert* and the zone in the *signed bundle*, so neither is redirectable without breaking a CA or config-signing signature; shadow-refusal at `deviceName()`, the signer backstop, and dual-control propose+commit; authoritative-before-forward precedence.
- **P11 (no bespoke crypto):** the entire zone + forward set rides inside the existing config-signing JWS ES256 bundle, verified before the resolver is configured; tampering breaks `Verify`. *Refused:* any separate signed-zone/DNSSEC-like format or side-channel feed.
- **TCB:** **zero new release-signing root** — `miekg/dns` (and CoreDNS plugins) are already/also in-tree, compiled into the existing Pilot binary. *Refused:* fetching/sha-pinning an external `unbound` via the bundle self-update path (that would join the fleet-RCE root). The one honest cost of the in-process pick is an **availability fault-domain** note (a resolver panic *could* crash Pilot) — bounded to a no-op for tunnels by fact 4, and belt-and-suspendered by the `recover()`-wall + caps.

## Split-horizon is convenience routing, not containment (honest reframe)

Do not oversell it. The **firewall** is the boundary; the DNS *view* is client-side routing convenience with **no confidentiality value on its own**. A `frontend` host denied the `corp.internal` zone can still query the target IP directly and will succeed **iff** some firewall rule permits `frontend → target:53` — and broad "services allow `:53`" rules are common and written outside this feature. Split-horizon holds only if no *other* rule exposes the target. The ADR states this plainly so nobody builds a security control on top of DNS scoping.

## TLS on mesh names (why the mesh-domain choice matters)

Mesh names are for humans; many of the services they point at (starting with the mesh-only admin console) are served over **HTTPS**, so the mesh-domain choice determines whether those certs can be **publicly trusted** or require a private CA. Decide it *before* Phase 1 picks an apex.

- **`.internal` cannot get a publicly-trusted cert — ever.** ICANN reserved `.internal` (2024) as a private-use TLD; the CA/Browser Forum Baseline Requirements forbid public CAs from issuing for reserved/internal names, and there is no way to prove control (no public zone, no CAA/WHOIS). Concretely, our own `internal/autotls` **cannot run** for `.internal` — its ACME **DNS-01** challenge has no public zone to write the `_acme-challenge` TXT into. So `.internal` ⇒ a **private CA** whose root is distributed to every host + browser trust store (smallstep `step-ca` / Vault PKI; Harbor could carry the root in the signed bundle). Note this is a **separate x509/TLS PKI** from the Nebula mesh CA (Nebula cert v2 ≠ x509), and **unmanaged devices** (a laptop not running Pilot — which the [[Nebula Control Plane - Runbook - Entra ID SAML SSO for the Console|Entra console runbook]] explicitly contemplates) need the root installed by hand.
- **A subdomain of a domain you own gets public trust *for free* — and we already have the machinery.** `internal/autotls` already issues **public Let's Encrypt** certs via **ACME DNS-01 (Cloudflare)** for the console/core-api/gateway (`autotls.go:1-12`, `cmd/harbor/serve.go:97`), and it chose DNS-01 precisely because **the box isn't reachable at its public hostname** — DNS-01 proves *control of the zone*, not *reachability of the host*. So a wildcard `*.mesh.<yourdomain>` issues cleanly **even though those names resolve only to `100.64/16` overlay IPs** via the split-horizon view. This is the Tailscale `*.ts.net` pattern.
- **Split-horizon and autotls reinforce each other — same domain, two horizons.** The **public** zone carries only the transient `_acme-challenge` TXT during issuance (and can be `NXDOMAIN` otherwise); the **private** (mesh) view carries the actual A/PTR records. The overlay IPs never appear in public DNS.
- **Keep the leak surface small.** Publicly-issued certs are **Certificate-Transparency-logged**, so *hostnames* (not IPs) become public. Use a **wildcard** `*.mesh.<yourdomain>` — one CT entry, no per-host name leakage — rather than a public cert per node.
- **Recommendation:** default to a **subdomain you own** so mesh TLS "just works" with zero trust-store rollout (including for unmanaged browsers); choose `.internal` + a private CA only when a fully-offline, no-public-domain posture is a hard requirement. This is a *deployment* choice carried by the `mesh_domain` site-setting, not a code fork — the resolver, bundle, and split-horizon design are identical either way.

## Phased plan

- **Phase 0 — Name-model hardening (ships value with zero DNS serving).** `deviceName()` normalize/uniquify/reserved-refuse; legal fallback; `signer.validate()` backstop; `dns_names` binding + migration `000032` backfill; `ipam.ensureDevice` re-key on `overlay_ip` / hard-fail; reaper clears `dns_names` on free; `harbor dns backfill|names`.
  - **Done when:** every issued/renewed cert `Name` is a unique, valid LDH label; two distinct hosts requesting the same name get distinct labels (stable `-n` suffix) with **no** silent `devices`-row collapse; no host label equals a reserved label; a recycled IP never inherits the prior owner's label; `harbor dns names` lists a sorted, byte-stable, **ghost-free** name↔overlay_ip zone; a test proves fresh-enroll and renew yield the same label for a given `overlay_ip`.
- **Phase 1 — Auto node-zone MVP (ask A), Linux/systemd-resolved.** `internal/meshdns.Zone()` (sorted, live-intersect + hysteresis, baseline CP/LH); `bundle.DNS.Zone` wired at **both** build sites (fail-open + keep-last-good); embedded `miekg/dns` in Pilot (loopback bind, atomic zone swap, `REFUSED`-on-miss, `recover()`-walled + caps); reverse PTR; systemd-resolved routing-domain applier via `resolvectl` (no capability, `ProtectSystem` intact); drift-revert re-asserts routes without touching `resolv.conf`. **Do the loopback-deliverability spike first.**
  - **Done when:** on a live Linux 3-node mesh, `getent hosts web-3.mesh.internal` resolves from the cached bundle **with Harbor stopped** (P3 proof); a dup/bad requested name cannot shadow `harbor.<domain>`; the zone is byte-stable across drift (no churn); PTR resolves; systemd-resolved's global config is provably untouched.
- **Phase 2 — Split-horizon forwarding (ask B) + governance.** `dns_forward_zones` registry + per-host group compile; `bundle.DNS.Forwards`; `dns.forward` dual-control Kind + `dns:write` RBAC + step-up MFA; P10 shadow-refusal at propose+commit; overlay-CIDR-only target validation; auto-allow `udp/53`+`tcp/53` companion rule + publish-time firewall-path check; thin CoreDNS-plugin forward/cache; `harbor dns forward add|remove|list`. **Plus the default-forward path (ask C):** `dns_netblock_forwarders` + fleet-default site-setting, per-host resolution from `sub_range`, `bundle.DNS.DefaultForwarders` + `CaptureUpstream`, and the **primary integration posture** (point the host's default resolver at Pilot); `harbor dns forward-default set|show`.
  - **Done when:** a dual-control-approved `dns forward add corp.internal --server 100.64.0.10 --group backend` makes `corp.internal` resolve **only on-mesh, only for `backend`**; everything else stays on the host's normal resolver; a non-overlay target and a mesh/CP shadow are refused at **both** propose and commit; the zone is unreachable off-mesh. In the **primary** posture with no split match, `example.com` reaches the host's **netblock-local** forwarder (or its **captured upstream** when unset) — never a blackhole; a per-netblock override sends a us-east host to the us-east cache and an on-prem host to the on-prem cache.
- **Phase 3 — Fast propagation, cross-platform, console, escape hatch.** Dedicated `dns` rollout lane (`Version` + `applied_dns_version`, canary→waves, freeze-on-unhealthy) + `harbor dns status`/`doctor`; Windows NRPT + macOS `/etc/resolver` appliers (rides **M10**); optional shared forward-cache pair; UI-6 "Naming & DNS" console.
  - **Done when:** an operator pushes a forward-zone change fleet-wide in minutes with auto-freeze on an unhealthy canary; Windows and macOS hosts resolve `*.<domain>` + forward zones with Harbor down using native split-DNS and no global-resolver hijack; the console can add/list forward zones and show lane convergence.
- **Phase 4 (deferred).** Group-namespaced aliases `<label>.<group>.<mesh>`; per-group node-record subsets (shrinks the fleet-global map exposure); DoT to forward targets; negative-cache/TTL tuning; per-zone metrics in the fleet view; attested/authorized names for a reserved-sensitive-name set (closes the squatting residual).

## Consequences

- **Positive.** Both asks land on the existing signed-bundle/render/drift/rollout/dual-control machinery — the incremental surface is one Go resolver + one `Registry` + per-OS appliers. No new TCB root, no new crypto, one cross-platform binary. Phase 0 is a standalone correctness win (unique, DNS-safe names + a real `dns_names` constraint + the `ensureDevice` collapse fixed). Split-horizon confidentiality is structural. Resolution survives Harbor being down.
- **Residual risk — name squatting (accepted, documented).** With auto-derive + auto-suffix, an enrolled member (compromised low-value host, malicious insider, CI enroller) can request `RequestedName=db` before the real `db` enrolls, taking canonical `db.<domain>` while the real host becomes `db-2`. The squatter's cert is *legitimately signed* with `Name=db`, so a client that resolves `db.<domain>`, connects, and checks `peer.Cert.Name == "db"` reaches the **wrong host** — a confused-deputy that the "DNS is not a boundary" argument does *not* cover for **traffic misdirection** (it only covers identity-forgery, which the firewall + cert still prevent). Reserved-namespace protection covers only CP/LH labels. **Accepted for v1** on the stance that names are convenience and enrollment is already authenticated; **mitigation deferred to Phase 4** (attested/authorized names for a sensitive-name set, per the §4.3a "groups from immutable facts" pattern). Flagged here so nobody builds `peer.Cert.Name`-based trust on a squattable name.
- **Residual — fleet-global name map exposure.** Every host's signed bundle carries the whole name↔overlay-IP topology, including hosts it is firewall-forbidden to reach; one compromised host exfiltrates the internal directory. The "nebula already exposes peer IPs via the lighthouse" rationale is *weaker* than it sounds (the lighthouse reveals addresses on-demand for peers you're establishing tunnels to, not a full forbidden-host directory). Accepted in v1; per-group node-record subsets (Phase 4) shrink it.
- **Residual — privilege crossing on the auto-allow rule.** A `dns:write` holder synthesizes `udp/53`+`tcp/53` firewall allows to operator-named overlay IPs, bypassing `policy:write` and its rollout lane. Bounded by default-deny + `dns.forward` dual-control + overlay-only targets; a tighter policy co-sign is a Phase-3 option.
- **Residual — primary-posture visibility.** In the *primary* integration posture Pilot is the host's default resolver, so it **sees all** of the host's DNS (not just mesh + forward zones). It stays loopback-local, but Pilot's telemetry could capture query names → default to **counters**, make full query-log **opt-in/sampled**, and document it. (The *scoped* posture avoids this — Pilot sees only mesh + forward zones.)
- **Operational.** The loopback-via-split-DNS deliverability spike is a real gate; the verified TUN-address fallback de-risks it. `dns doctor` should land as early as feasible (a systemd-resolved-present-but-not-in-`nsswitch` host silently `NXDOMAIN`s). Drift-revert re-asserts per-link `resolvectl` state, not the `resolv.conf` file — usually fine on the unmanaged TUN, but note it if a link manager is told to own the nebula link.

## Open questions to resolve before building

1. **Mesh domain apex — and the TLS consequence.** Ship the demo on `mesh.`, but for production **recommend a subdomain of a domain you own (`mesh.<yourdomain>`)** so publicly-trusted TLS issues via the existing `autotls` DNS-01 flow with no trust-store rollout (see §"TLS on mesh names"); `.internal` is collision-proof but forces a private CA. Which apex — an owned subdomain (public TLS) or `.internal` (private CA)? (Dual-control-gated; decide before Phase 1 goes wide.)
2. **Collision policy toggle.** Default is auto-suffix (unattended-safe). Do we also want an attended-enrollment "hard-reject on collision," and a **rename API** — or is "name follows `RequestedName`, converges at renewal" acceptable for v1?
3. **Per-group node-name views.** V1 puts the whole mesh name↔IP map in every host's bundle. **Recommend fleet-global in v1**, per-group node-record subsets deferred to Phase 4 (forward zones are per-group from day one regardless). OK to expose the full name map fleet-wide?
4. **`/etc/resolv.conf` posture on non-systemd-resolved Linux.** **Recommend split-DNS as the only default**, plus an opt-in **guarded capture-mode** (engaged only when Pilot demonstrably owns a plain, non-symlink `resolv.conf`; never seize a manager symlink; else degrade to "resolver up, operator points it"). Ship capture-mode, or keep such hosts operator-wired?
5. **Escape-hatch timing.** Keep the shared `unbound`/CoreDNS forward-cache **default-OFF and deferred to Phase 3**, or is there a concrete early need (heavy/flaky internal upstreams) to bring it into Phase 2?
6. **Fast-lane timing.** Is drift-cadence propagation acceptable for the forward-zone MVP with the `dns` rollout lane deferred to Phase 3, or do you want canary→waves for forward zones from their first release?
7. **Default integration posture (ask C).** *Scoped* split-DNS (Pilot sees only mesh + forward zones; the OS handles everything else) vs *primary* resolver (Pilot is the host default; the default-forward path handles the rest; required for capture-mode). **Recommend scoped for Phase 1, primary in Phase 2.** Which should be the default for most of the fleet?
8. **Default-forward fallback + governance (ask C).** When no per-netblock/fleet forwarder is set, fall back to the host's **captured pre-existing upstreams** (non-destructive — queries go where they already went)? **Recommend yes.** And should per-netblock/fleet default-forwarder changes be **dual-control** (they steer all of a host's public DNS)? **Recommend yes + audit**, even though the targets may be underlay. Also: is a single ordered forwarder list per netblock enough, or do you need per-netblock *conditional* rules (e.g. some suffixes to cache A, the rest to cache B)?
